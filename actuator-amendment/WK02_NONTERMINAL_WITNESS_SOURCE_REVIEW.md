## Scope and source diff
Branch codex/wk02-m3-nonterminal-witness is isolated from Work PR62 and Chat's terminal-inactive candidate. It adds `BTMS_WK02_nonterminalWitness.m` and modifies the existing `BTMS_M3_requalifyEntry.m` only to fail the MATLAB action when the private flags remain UNQUALIFIED. It does not edit the model, physical network, solver, controller, actuator period, current load, reference or vendor source.

The function is intentionally source-clone pinned and cannot be passed the 30 ms toy as a substitute for the physical clone; the existing fixture does not call it. Re-running the disabled fixture unchanged would not validate this function. A separately reviewed synthetic adapter would need its own toy identity and explicit mode/terminal metadata before any nonbattery dispatch.

The recorder requires the caller's pre-step `processedPriorTop`, the actual `finalstep=false`, paused status and finite nonregressing next `s.Time`. It invokes the existing four-role bounded signal and phase helper, records four *per-step native tail clocks*, source/clone SHA pins, pre/post actuator DState and output, and ordered phase sequence. Those four tails do not replace four complete ToFile timestamp vectors. It rejects any terminal step before interpreting it as a completed-major witness. Callback records retain only their actual phase semantics.

The source/clone SHA strings are compared and recorded, but true byte integrity depends on an independent owner-private preflight, not a caller-supplied boolean alone. The caller must bind the actual clone hash to the SHA-verified M2 receipt and verify it again after remote readback; this function does not itself prove cryptographic provenance.

## Separate terminal receipt contract
The future driver must stop collecting accepted-major witnesses at the last **nonterminal** step within the prespecified event window. It then completes the same trajectory to the frozen horizon and records actual finalstep/Status/returned-Time availability, configured mode, `SimulationOutput.SimulationMetadata.ModelInfo.SimulationMode` and `ExecutionInfo.StopEvent/StopEventTime` if supported, and `ErrorMessage`. A separate private reader checks all four full ToFile native clocks, original duplicates, last samples and SHA. Terminal `inactive` or unavailable Time is NEVER a new accepted major hit; if mode/stop reason remains ambiguous, classify UNQUALIFIED. Owner-private JSON schema from read-only run 40800167858 was inspected without copying MAT: its keys are sourceRun, auditRun, commit, inputSHA, lifecycle, checkpointCount, nativeClockSummary, nativeLastPresent, physicalRun and G5Accepted. Its lifecycle records finalStepReturned, majorCount, processedPriorTop, returnedSimulationTime and simulationStatus. It contains no effective SimulationMode or StopEvent field. The old 30 ms toy had finalstep true but inactive and no returned Time; that saved schema cannot establish the lifecycle cause.

## t0/IC fail-closed plan
Before physical use, inventory every continuous/discrete Simulink and hidden Simscape state in the cloned source and demonstrate a **documented R2024b** way to obtain a complete operating point at t0 from the same initialization that begins B0L and C0. Save full object, version/model checksum, source/clone SHA and the actual t0 timestamp; verify restore/replay parity on an independently authorized nonbattery qualification. A first-paused operating point is after the first major step, not t0; an archived warning says block reduction may prevent restoring that object. T312, initial block parameter equality or a saved first-paused OP cannot reconstruct full hidden t0. The archived run does not demonstrate a supported t0 capture method. This is `WK02_NO_GO_IC`, not a claim that R2024b can never support such a method.

## Bounded resource estimate and single next validation gate
At 340 s and 10 ms, one T312 double sample per tick has a lower bound of 34,001×312×8 = 84,866,496 bytes (~80.9 MiB) before timestamps, duplicates, HDF5 overhead and state/logging copies. At a hypothetical 5 ms observation cadence the T312 lower bound doubles (~169.7 MB); this is a planning bound, not permission to change Ts. Prior M2 policy caps each native file at 1 GiB, all four at 2 GiB, retains 2 GiB RAM/disk and 512 MiB private-delivery reserves, 1200 s trajectory and 300 s delivery ceilings. Actual peak and current free quota require fresh measurement. The existing owner-approved physical one-shot remains unused.

**One recommended next gate:** a separate source/runtime review must demonstrate a viable full t0 operating-point witness and a mode/StopEvent terminal receipt on the exact installed R2024bU10, with no battery, before any one-shot validation of this recorder. If t0/IC cannot be certified, retire this approach for thermal inference and use a separately reviewed full-state initialization protocol. No automatic trial is authorized here.
