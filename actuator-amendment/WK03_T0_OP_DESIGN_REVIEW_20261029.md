## Candidate A: zero-stop full operating point

On a separately authorized, isolated derivative (first a nonbattery fixture, later the exact pinned physical clone), construct `Simulink.SimulationInput(model)`, then set `StartTime='0'`, `StopTime='0'`, `SaveFinalState='on'`, `SaveOperatingPoint='on'` on that simulation input only. Run `out0=sim(simIn0)` and require `isa(out0.xFinal,'Simulink.op.ModelOperatingPoint')`, finite `op0.startTime==0`, `op0.snapshotTime==0`, no error, observed normal mode, and `ExecutionInfo.StopEvent='ReachedStopTime'` if the field exists. Save the *entire object*, not only `loggedStates`: MathWorks says hidden states, solver state and execution engine state are in the complete object, while Simscape contents need not appear in `loggedStates`.

This is **not yet an initialized-before-step t0 certificate**. Exact R2024b Stop time documentation says StartTime=StopTime executes **one step**. The object may represent the state *after* processing the t0 major hit, even with `snapshotTime==0`. Record native t0 output/phase order and explicitly test restore parity; do not call this a pre-update IC from its timestamp alone. Do not copy the object between structurally different B0L and C0 clones. Retain source current, 300 K reference, initial parameters, original ode23t settings and sampled-actuator law.

For each case independently, create `simInRestore=Simulink.SimulationInput(sameModel)`, call `setInitialState(simInRestore,op0)`, set the original StartTime 0 and a separately approved short StopTime greater than 0, then compare a direct run and restored run from the same model/workspace. Compare t0 first/last phase, completed-major clocks, all four native stream clocks, actuator state/output, T312 and documented visible state; include duplicate timestamps. Fail on a replay mismatch or an initial-state/checksum diagnostic. This proposed *nonbattery* fixture cannot establish full Simscape parity; physical proof would require a separately approved clone-specific qualification. No run is authorized by this document.

## Candidate B: initialize then capture at zero

`initialize(s)` is documented to compile and leave the simulation `Status='initialized'`. The documented `CurrentOperatingPoint` method obtains an object when a simulation is **paused**, while `step(s)` advances one major step and then pauses at the next top. We found no documented R2024b guarantee that `get_param(model,'CurrentOperatingPoint')` on a merely initialized `Simulation` object returns a complete, restorable pre-step t0 object. Thus B is `UNSUPPORTED_BY_DOCUMENTATION`, not a fallback that can be silently used. The earlier first-paused OP at positive time is not t0.

## Block reduction, checksums and fail-closed parity

R2024b ModelOperatingPoint documentation warns that loading an OP disables Block reduction; if Block reduction was enabled while saving, restoring may fail. Read and record the exact frozen clone's `BlockReduction` value and compiled structural checksum. If it is `on` or unavailable, do not flip it to force a test or claim original-graph parity; return `BLOCK_REDUCTION_PARITY_UNQUALIFIED` for owner/source review. Any proposed clone-only setting change must be separately reviewed against source configuration and its effect on compiled graph. Do not loosen operating-point mismatch settings, ignore warnings, or infer hidden Simscape states from T312.

Preflight must independently hash the actual source SLX, clone SLX, relevant workspace/parameter files and input data bytes, and bind their SHA-256 values to source tag 24.2.1.5, MATLAB R2024b Update 10, solver/tolerances, load, 300 K reference, actuator period and model config. Record model structural checksum from actual `SimulationMetadata.ModelInfo` when supported. An input receipt SHA is a provenance reference; a caller-supplied boolean is not attestation. Postflight must independently hash the *new* OP/MAT/native outputs after private Drive upload and remote readback. Never use input preflight to claim output readback.

For B0L and C0, prove restore parity **within each case** before using a common-state comparison. If a common full physical t0 is required, establish it from complete compatible operating points and same load/IC contracts; do not equate different control states or compare only 312 observed temperatures. Exact OP internal checksum fields need not be exposed; preserve the whole object and fail on any restore checksum or compatibility error. Do not rely on R2025a-only flexible OP mismatch behavior.
