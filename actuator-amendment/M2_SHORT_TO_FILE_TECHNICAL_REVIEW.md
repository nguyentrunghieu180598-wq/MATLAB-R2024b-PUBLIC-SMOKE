## An implementation that does NOT require R2025a
[Official Simulink To File block](https://www.mathworks.com/help/simulink/slref/tofile.html) incrementally writes an uncompressed v7.3 MAT and supports **normal** simulation, including model output vector data. Explicit block props: FileName, MatrixName, SaveFormat=Timeseries, Decimation=1, SampleTime=-1. It is independent of the R2025a-only Simulation-object logging-to-file support. `LoggingToFile` for R2024b may be used with **classic normal batch sim**, but is incompatible with stepper and fast restart. Mixing these without verifying semantics is disallowed.

**Actual prepared Chat code:** `jte-public/BTMS_M2_prepareShortToFile.m` in branch `chat/jte110-g5-math-canary`, commit `995294b89550b8cb044e4b55c802afd57eaa0405`. Static preparation only; never invokes sim/compile. Requires an approved source 10/5ms SLX, new derivative file path, existing owner-private output dir, frozen R2024bU10 and existing SHA helper. Creates exactly FOUR output taps on a cloned model: (1) source core u, (2) sampled command ZOH, (3) actuator output y, (4) all 312 Ttrue. These are separate To File files, each with its own **original** timestamps and duplicate rows (no implicit equality or interpolation). It does NOT disable existing original model logging, so it has not yet demonstrated reduced peak RAM. Source full parameter/graph, compile and source file hash must be checked independently on the generated clone.
